## 书写区高度固定（修复）

问题：`{count === 0 && <PromptChips/>}` 条件渲染，一打字便签整块消失，卡片从 591px 缩到约 410px，纸面跳动。

解法：便签改为**常驻占位、只淡出**（`opacity-0` + `pointer-events-none` + `inert={count>0}`），高度天然不变；同时把横格从 textarea 移到一个绝对定位的 `.ruled-field` 图层，铺满整个书写区，便签隐去后露出的仍是连续横格。

关键坑：绝对定位以**内边距盒**为基准，外层 `pt-2` 会让图层比 textarea 高 8px，横格就偏了。必须写 `absolute inset-x-0 top-2 bottom-0`（top 值等于外层 padding）。已实测 layerTop == textareaTop == 176。

验证：桌面与移动端填写前后 `form` 高度均 591 → 591，`scrollWidth` 无溢出。

## 便签区格线穿透（修复，第二轮）

上一版让横格铺满整块书写区，导致**空态时格线穿过灵感便签**，且便签高度与 34px 格距不同步，看起来稀密不均。

解法：灵感便签条改成**一段压在格线上的纸带**——`bg-paper-soft` 实色底 + `border-t border-dotted`，自身底色盖住下方格线；落笔后整条（含边框）淡出，格线自然接续。高度仍靠常驻占位保持。

- `.ruled-field` 加底部 18px 的 `mask-image` 渐隐，避免纸边裁出半截线。
- `PromptChips` 根节点 `mt-4` 去掉，间距交给纸带 `pt-3`。
- 实测：格线间距全部 34px；末线到分隔线 17px；`form` 高度 604 → 604（桌面/移动一致）。

## 背景改用 three.js（用户回滚了竖线方案）

- 装了 `three@0.187` + `@types/three`；**three 0.187 不自带 d.ts**，必须装 @types。
- `paper-scene.tsx` 重写：CSS 光晕/光束/暗角保留，画布换成 WebGL。
- 场景：220 张纸笺（桌面）/110（小屏），每张只是 `LineSegments` 的 4 条边，3D 随机翻转 + 上下浮动；560 个光点用 `Points` + 自定义 shader（`gl_PointSize` 随距离衰减）。
- 滚动：`progress = scrollY / (scrollHeight - innerHeight)`，相机 z 走到 -150（lerp 0.06），卡片落到身后就 `z -= 210` 循环。滚到 45%→95% 时卡片转动阻尼加大，逐渐正面朝向（“散页被风排齐”）。
- 指针：相机位置 ±3.4/2.2，lookAt 也带一点偏移，形成视差。
- 着色器里用 `1.0 - smoothstep(near, far, d)` 做距离淡出；**不能写 smoothstep(200,40,d)**（edge0>edge1 在 GLSL 里未定义）。
- `THREE.ColorManagement.enabled = false`，让 shader 直接输出 sRGB 十六进制值，否则颜色偏暗。
- three 用 `await import("three")` 延迟 240ms 加载，失败则悄悄退回纯 CSS 背景。
- 实测：DPR 上限 1.75 → 画布 2240×1575；SwiftShader 软件渲染 26fps（真机 GPU 应 60）；无报错。
- **Windows 构建前必须先杀 3000 端口**，否则 next build 卡在 Experiments。
