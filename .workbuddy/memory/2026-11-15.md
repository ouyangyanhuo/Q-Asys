## 书写区高度固定（修复）

问题：`{count === 0 && <PromptChips/>}` 条件渲染，一打字便签整块消失，卡片从 591px 缩到约 410px，纸面跳动。

解法：便签改为**常驻占位、只淡出**（`opacity-0` + `pointer-events-none` + `inert={count>0}`），高度天然不变；同时把横格从 textarea 移到一个绝对定位的 `.ruled-field` 图层，铺满整个书写区，便签隐去后露出的仍是连续横格。

关键坑：绝对定位以**内边距盒**为基准，外层 `pt-2` 会让图层比 textarea 高 8px，横格就偏了。必须写 `absolute inset-x-0 top-2 bottom-0`（top 值等于外层 padding）。已实测 layerTop == textareaTop == 176。

验证：桌面与移动端填写前后 `form` 高度均 591 → 591，`scrollWidth` 无溢出。

## 便签区格线穿透（修复，第二轮）

上一版让横格铺满整块书写区，导致**空态时格线穿过灵感便签**，且便签高度与 34px 格距不同步，看起来稀密不均。

解法：灵感便签条改成**一段压在格线上的纸带**——`bg-paper-soft` 实色底 + `border-t border-dotted`，自身底色盖住下方格线；落笔后整条（含边框）淡出，格线自然接续。高度仍靠常驻占位保持。

- `.ruled-field` 加底部 18px 的 `mask-image` 渐隐，避免纸边裁出半截线。
- `PromptChips` 根节点 `mt-4` 去掉，间距交给纸带 `pt-3`。
- 实测：格线间距全部 34px；末线到分隔线 17px；`form` 高度 604 → 604（桌面/移动一致）。

## 明暗四档（白昼 / 夜读 / 依时 / 随系统）

- 新增 `src/lib/theme.ts`：`ThemeMode = day | night | clock | system`，`resolveTone()` 统一裁决；`applyTone()` 落 DOM（夜间 `data-theme="night"`，白昼移除）并同步 `style.colorScheme`，同时派发 `qasys-theme-change`（AmbientLight 靠它无感切换）。
- 存储键改为 `qasys-theme-mode`，兼容旧键 `qasys-theme`（只存 day/night）。默认 **clock**（依时）：18:00–07:00 为夜。
- `theme-toggle.tsx` 从「点击即翻面」改成**弹出小菜单**（`bottom-full` 或 `top-full`，`placement` 参数；页脚传 `top`），四档单选，自动档带朱砂小点。
- 自动档的守护：30s 轮询（跨过 18/07 点即换）、`visibilitychange` 回前台补算、`matchMedia('(prefers-color-scheme: dark)')` 监听随系统、`storage` 事件跨标签同步。
- `layout.tsx` 的 head 内联脚本同步改写：先读 mode 再算 tone，首屏不闪白。**改时辰阈值时三处要一起改**：`theme.ts` 常量、内联脚本、菜单里的 `18–07` 提示。


## 输入净化与限流（安全加固）

- 新增 `src/lib/sanitize.ts`：长度粗筛（max×20）→ NFC 归一 → 剔零宽/双向/控制字符 → 危险标签·事件属性·`javascript:`/`data:text/html` 直接拒 → 高置信 SQL 载荷拒 → 普通标签剥离 → 折叠刷屏重复 → 码点计数（含 `\p{L}\p{N}` 判空）。
- 新增 `src/lib/rate-limit.ts`：三维度固定窗口（来源 3/60s、来源 5/1h、全站 40/1h），`checkRate()` 先计数再判断，超限返回 `retryAfter`；计数表异常时 **fail-open** 并告警。
- 存储层：`countRecentByIp`（按 questions 表统计）**删除**，改为 `hitRateCounter(key, windowSeconds)`；neon 用单条 `insert … on conflict do update … returning hits` 保证跨实例原子；local 用进程内 Map（仅开发）。`db/schema.sql` 新增 `rate_counters(key, window_start, hits)`。
- `actions.ts`：蜜罐 → 正文净化 → 落款净化（单行）→ 限流 → 参数化写入，错误返回 `{status, code, message, retryAfter?}`，不回显原文。
- `admin-actions.ts`：回信也走净化（MAX_ANSWER=2000），id 先用 UUID 正则卡一道。
- 顺手修 `/q/<非 UUID>` 会 500 的 bug：`neon-store.getQuestion` 先验 UUID，不合法直接返回 null。
- 上线注意：Neon 里补跑 `rate_counters` 建表语句，否则限流处于 fail-open（不报错但也不生效）。
